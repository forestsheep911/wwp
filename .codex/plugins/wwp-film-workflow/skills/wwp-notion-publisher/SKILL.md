# WWP Notion Publisher

Publish playable outputs and prove the library state. Prefer existing WWP repository tools over rewriting Notion API logic.

## Workflow

1. Confirm the work page or create one only when the work is genuinely new.
2. Reuse existing work pages for supplemental specs.
3. Title every newly created or currently touched spec page with the canonical grammar from `../../references/notion-media-assets.md`: short canonical Chinese work title, explicit original/dubbed audio label, explicit subtitle treatment, measured resolution, codec, and exact decimal-GB display size, in that order. Do not repeat the parent English/original title or year, omit the audio nature, or use internal high/medium/low tier words.
   Derive the displayed size from the exact final file byte count using the workflow's decimal-GB convention. Do not inherit a stale size from a filename or an existing placeholder page; a materially different size requires a corrected or separate spec page.
4. Create or reuse the target spec page before encode starts whenever manual upload may be needed. A reused movie spec page is a valid destination only when it contains no video block. If it already contains media, report the existing asset and stop the new encode unless a deliberately distinct specification has been approved. Notion API cannot move an already uploaded media block into a different child page in this workflow; report the target page ID before the user uploads and do not rely on later root-level cleanup.
   An explicit movie `--target-page-id` or series `--target-spec-page-id` must be re-enumerated under the requested work/series page immediately before upload. Refuse a target outside that parent, even if the supplied page ID exists. Supplying only a spec title is insufficient; use the exact checked ID, or use explicit `--create-spec` during structure creation. Never let an upload command implicitly select or rename the first existing spec page.
5. If the work page/spec page exists but upload is slow, deferred, or not yet suitable, route to `wwp-metadata-backfiller` immediately and continue upload work afterward or in parallel.
6. Upload playable MP4 files automatically with the mapped repository tool by default. For series, upload one file to each Episode page unless collection delivery was explicitly requested. Before creating any upload session, enumerate every selected Episode target: an existing video block, including an unnamed Notion-hosted block, is a hard stop for that Episode and the batch. Inspect and reconcile it first; never upload a second file merely because the existing block has no filename/caption. Use a manual-upload handoff only after the route preflight is too slow, bounded automatic retries fail, or the user explicitly chooses manual upload; name every prepared destination page and ID.
7. Before any Notion access or transfer, probe each final local file. Reject a video with no video stream and reject HEVC/MP4 unless `codec_tag_string=hvc1`; losslessly remux `hev1` to `hvc1`, then re-probe it. This is a pre-upload gate, not a later Media Assets correction.
8. Before a large API upload, run a small multipart route probe with the normal `api.notion.com` hostname. On Clash-based hosts, verify that the connection matches the Notion direct rule rather than a generic proxy fallback. Use at least `2 MiB/s` as the default safe-start floor for a near-5GB file; below that, stop before consuming the one-hour upload window.
   If an unbound direct upload starts materially below that floor, stop it early rather than waiting for the one-hour session to fail. Re-resolve the current Notion API address and retry the same resumable manifest with `--resolve-ip <api-ip> --local-address <physical-lan-ip> --no-proxy`. Previously accepted multipart parts must be reused. Re-detect both addresses for every run and retain concurrency 1; the measured improvement is evidence for that run only, not a permanent hardcoded route.
9. For large Notion file uploads, keep the upload manifest and command log. Retry the same multipart part with bounded exponential backoff for transient transport and gateway failures, and advance the manifest only after that exact part is accepted. Treat only a `409` whose message explicitly says `Failed to upload file. Please try again later.` as transient; an ordinary `409` remains a fail-closed resource conflict. If the process is interrupted, rerun the same command and resume from the accepted-part boundary instead of starting over.
   Keep AI ownership of the active upload until it reaches a terminal evidence state: poll the uploader process, stdout/log, and resumable manifest at bounded intervals. A process that has exited, a manifest whose accepted part does not advance, or a missing uploader process means the upload is not active; resume the same manifest or record a deferred/manual-handoff state. Never leave a variant labelled `上传中` without an observed live process.
10. Probe the exact local final file and write Media Assets from `ffprobe` plus production manifest data. For series files still available locally, pass `--media-root <final-output-dir>` to the writer so `Approx Size GB` is measured from actual decimal bytes, never inferred from the spec-title range. Use a guarded batch manifest when broad title search can match sibling works. Include the exact Episode page ID because Notion may remove punctuation from the uploaded filename; after upload, prefer the observed Media Block ID for the final write or correction. Before release, read back and validate the exact Work relation, source page, Media Block ID, technical fields, measured size, and both the Media Assets `Name` and `Display Label`. For every newly created, renamed, or otherwise touched spec, both fields must exactly equal the canonical spec-page title; a correct child-page title with an empty/stale Media Assets title is a publication defect because the website may display it as `Untitled Notion page`. Repair `Name` and `Display Label` together only through an exact Work plus Media Block guarded manifest, then require direct readback and an idempotent rerun. A wrong Work relation or missing/wrong `Approx Size GB` is also a Media Assets metadata defect: repair the exact row with `tools/notion-media-assets-repair-work-relation.mjs`, then read it back. Do not create a duplicate row as a workaround.
11. Run readback or stats to prove the uploaded block and Media Assets row exist. For a manual upload with no caption, accept a sole unnamed media block only on the exact registered destination page, then persist its block ID; never guess among multiple blocks.
12. Release only automation-owned Media Assets visibility gates with `tools/notion-media-assets-release.mjs`. Dry-run an exact manifest first; require matching Work, source page, Media Block, Episode expectation, resolution, codec, container, size, playable availability, and verified playback. Set `expectedEpisodeNumber` to the positive episode number for series assets and explicit `null` for movies. The tool may clear only that asset row's `Hide from Website`; it must not clear a work-level or human-set gate.
13. Reconcile the exact variants until the local ledger reaches `sync_ready`; this closes only the playable publication gate. Before updating the work-page handoff to `已完成`, route the exact work page through `wwp-metadata-backfiller`/`wwp-library-maintainer` and require `Metadata Status=verified`, empty `Human Issue` and `AI Issue`, and a usable maintained poster. Keep a partial series or a published-but-metadata-incomplete work `AI 处理中`, record which gate is complete and the exact metadata fields still missing, and requeue/defer the metadata task instead of calling the current release complete. If the publisher changed the page directly, immediately run `notion-workflow-handoff reconcile` for the exact work page IDs so SQLite cannot retain stale actionable states.
14. Before the local incremental website sync, determine whether this run changed only Media Assets or child blocks. Those edits may not update the parent work page's `last_edited_time`, which would leave the site cache stale. In that case append a concise `【AI(^_^) ...】` audit marker to the existing `Workflow Note` while preserving its current `Workflow Status`; this is a sync invalidation record, not a new coordination channel. Then run the local incremental website sync and query the live API for the exact work. Completion requires every expected Episode and newly created Media Assets page ID to appear in the running site's result, not only in the on-disk index; it also requires a non-empty live poster and the core work metadata projection. A poster source that exists in Notion but cannot be fetched/cached fails this gate. For a series, run `node tools/series-index-variant-audit.mjs --work-page <work-page-id> --json`: `review_required` duplicate groups must be resolved or explicitly deferred before calling the release complete. A `distinct_size_tiers` group is allowed only with current separate QC evidence. `legacy_tier_title` identifies an older playable tier whose spec omits `/集`; correct it when that spec is touched, but do not let an untouched historical label block an otherwise verified current release. A count that stops at a configured variant limit is a publication defect, not successful readback.
15. If film-level metadata is still missing, route to `wwp-metadata-backfiller`.
16. After the first verified useful spec and the work-level metadata gate pass, clear the automation-owned work `Hide from Website`, sync, and read back without waiting for optional supplemental variants. Keep each unfinished supplemental spec hidden at its own asset/page level until its individual QC and publication gates pass.
17. Before setting work-level `Workflow Status=已完成`, append the latest `[规格扩展:OPEN]` or `[规格扩展:CLOSED]` AI marker from the concrete ledger decision. Do not create a separate Notion property; the exact selected/deferred ledger variants remain the queryable machine queue.

## Page Shape

New API-created content should prioritize stable structure, machine parsing, and Media Assets completeness. Historical visual structures such as base/toggle/callout layouts are compatibility targets when reading old pages, not requirements for new API output.

## Guardrails

- Default upload is playable only; source/original-disc upload belongs to `wwp-source-archive-operator`.
- Automatic upload is the normal playable publication path. A manual-upload status is a recoverable collaboration state, not a permanent property of the variant.
- Series collection files are disabled by default. Use one playable file per Episode page; pass the uploader's collection opt-in only after an explicit user instruction.
- Preserve the `api.notion.com` hostname for normal uploads so domain-based direct-routing rules can match. `NOTION_API_RESOLVE_IP` is a metadata/API failure workaround, not a large-upload default. Use `--resolve-ip` only as an explicit fallback after a hostname request fails, and inspect the resulting Clash route because a fixed IP can lose the Notion domain rule and fall into a paid proxy group.
- The series uploader keeps the configured proxy by default. When that proxy repeatedly resets the TLS connection before the request begins, retry the same structure or upload command once with `--no-proxy --resolve-ip <api-ip>`; this bypasses `NOTION_PROXY_URL` for that run without changing the machine-wide proxy configuration. Record which route succeeded in the workflow note.
- If Clash fake-IP `DIRECT` repeatedly fails TLS while a physical-interface request succeeds, bind the uploader to the current physical IPv4 address with `--local-address <lan-ip>` and pair it with a freshly resolved real Notion API address via `--resolve-ip <api-ip>`. Verify both values at run time; never hardcode a stale LAN or Notion edge address. This path bypasses the virtual adapter and must remain direct rather than consuming a proxy group.
- If an in-flight multipart part is clearly stalled and the local Clash controller is available, close only this uploader process's exact Notion connection and retry the same `file_upload_id` plus `part_number`. Never restart all Clash traffic or discard already accepted parts. Prefer fixing hostname/direct routing first; connection recycling is a bounded fallback.
- Early-created work/spec pages do not justify playable Media Assets rows; media evidence must come from a real video/file block or the exact final local file.
- Do not use work-page-root video/file blocks as final playable placement. If manual upload landed at the root, report the exact target spec/episode page and treat the block as structure-incomplete evidence. Because Notion API cannot move media blocks between pages, use manual move/reupload by the user, or explicit local-file reupload only when accepted. For future work, run the prepare-only page-creation step before encode or handoff so this cleanup is not needed.
- Do not collapse distinct Chinese audio variants into one generic spec. When filenames identify `zh-mandarin`, `zh-cantonese`, or `zh-taiwan`, prepare separate `国配`, `粤配`, and `台配` spec pages unless the user explicitly asks to merge them.
- Do not trust `Chinese`/`zh` source labels or an unverified filename marker as proof of Mandarin. If multiple Chinese streams exist and the mapping is unknown, keep the target language unconfirmed. A user listening report is valid evidence: rename/reuse the target as `粤配` when the user identifies Cantonese, and do not create a `国配` page until a Mandarin stream is independently verified.
- The workflow owns `Hide from Website`: keep it true until playable media, Media Assets, subtitles required by the selected branch, and QC are all verified, then clear it during the authorized publish step. A verified `国配` branch requires no Chinese subtitle for release; record missing subtitles as optional later enrichment and do not keep the branch hidden for that reason alone.
- Optional planned high/balanced bitrate, alternate audio, subtitle, commentary, or cut variants do not keep an otherwise verified work hidden. Release the work after one useful spec passes every release gate; gate later variants individually.
- Clear the visibility gate only after the exact uploaded block, `ffprobe`-backed Media Assets row, QC evidence, and ledger reconciliation all pass. For a partial series, keep any episode whose codec or audio compatibility cannot be verified hidden, while already verified sibling episodes may release. Record the unresolved episode and the required next input in `Workflow Note` with the `【AI(^_^) ...】` marker; preserve human plain-text notes and acknowledge them with a later AI marker.
- Set or keep `Needs Review` when upload/readback evidence is incomplete, Media Assets disagree with the page, subtitle/audio/QC is uncertain, or a human decision is pending. Do not treat clearing review as permission to unhide the work.
- Do not infer codec, duration, frame rate, audio, subtitles, or resolution from filenames when final media can be probed.
- Do not treat an accepted final multipart part as publication completion. The file upload must be completed, the media block appended to the exact destination, Media Assets written and read back, the ledger reconciled to `sync_ready`, and the live site queried successfully.
- Configure website ingestion to retain the complete expected Episode set. `NOTION_VARIANT_LIMIT` must be at least the largest published series in scope; the current local default is 200. Verify continuity as well as count so a newly added Episode cannot silently evict an older one.
- Do not mark the current release complete from local logs, `sync_ready`, or Media Assets readback
  alone; require exact metadata verification plus live playable, poster, and
  core-metadata readback.
- Do not require a persistent Asset URL for Notion-hosted uploads when the URL is a temporary signed file URL; durable page/block IDs are the stable proof.

## Bounded Naming Checks

- Spec-title consistency checks are targeted follow-up work, not a reason to enumerate the full library.
- Inspect only the exact specs touched in the current run or the latest small set of production/upload targets, normally no more than 3. For series, verify that the title uses a per-episode size or range such as `0.8-1.0GB/集`, never the season total.
- Within that bounded set, normalize every touched sibling spec to the same token order and vocabulary. A touched work must not retain a mix of full bilingual parent titles, English-only titles, omitted codecs, bare language names, or ambiguous `中文原声` labels when the facts are known.
- Do not use a recent-page watcher or broad title search to discover more naming problems. If an older spec was not touched, leave it alone unless the user names it or a later workflow step reaches it.

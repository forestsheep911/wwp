# WWP Playable Encoder

Use this skill for playable outputs that people will watch directly. Source archive handling is separate.

## Defaults

- Output directory: explicit request/configuration (`WWP_OUTPUT_ROOT`). Only Windows retains `E:\video_made` as a legacy default. On macOS, follow `../../references/storage-rules.md`; never interpret a Windows drive path as a local directory.
- Container: MP4.
- Codec direction: HEVC preferred unless the user asks otherwise or compatibility requires another choice.
- HEVC/MP4 browser compatibility: explicitly mux the video track as `hvc1` (for ffmpeg, `-tag:v hvc1`). Do not ship an `hev1` sample entry as Android-browser compatible merely because the codec is HEVC and the MP4 is faststart.
- Subtitle delivery: burn selected Chinese subtitles into the video for subtitle-dependent versions; when the source already has a verified hard subtitle, use the no-subtitle-stream path and record that fact instead of attempting to overlay a nonexistent stream. PGS/bitmap subtitles use `--subtitle-stream`; ASS/SSA/SRT text subtitles must first be extracted to a subtitle file and use `--subtitle-file`, which routes through the text-subtitle filter. If the sidecar is not UTF-8, pass its verified source encoding with `--subtitle-charenc` (for example `GBK`) and inspect a known dialogue timestamp. Do not send an embedded SRT stream to the bitmap-overlay path: it can produce a video with no visible burned subtitles despite subtitle packets being present.
- Mandarin-language films and verified Mandarin-dubbed (`国配`) variants: prefer no hard subtitles unless subtitles are already burned into the source and cannot be separated. A verified `国配` output with no Chinese subtitles remains eligible for normal encode, QC, publication, and completion.
- Size target: keep Notion-bound playable MP4 files below the workflow cap of 5,000,000,000 bytes unless the user explicitly changes it. Official Notion wording may use 5 GiB, but this workflow keeps the lower decimal-byte cap as upload safety margin. For high-bitrate manual-upload candidates, usually aim for about 4.7-4.9GB, never a 6GB upload candidate.
- High-bitrate acceptance is based on the measured final file, not the spec title or `target_size_bytes` alone. When a selected high tier is intended to be 4GB-plus, a final file below 4,000,000,000 bytes is a production mismatch: keep it out of `qc_passed`/publication, record the measured size, and re-encode with an explicit `--video-bitrate` calculated from duration and audio overhead. Do not let a CQ encode silently satisfy a size-oriented high tier.
- Before a full encode, check free space on the output volume for the work MKV, MP4 remux, and final file together. Budget by actual volume identity, not directory names: a shared work/output volume requires roughly `3 * max-bytes + 512MiB` for work, remux, and verified target staging; separate volumes require `2 * max-bytes + 512MiB` on temp and `max-bytes + 512MiB` on output. Bounded smoke samples use a smaller reserve.
- Dolby Vision/HDR sources require an explicit, validated color-management path before SDR delivery. Do not feed a 10-bit DV source directly into an SDR NVENC encode and infer that the result is correct from the output metadata.
- CQ is a quality target, not a byte-size contract. During a long encode,
  project final bytes from the advancing work-file size and encoded duration.
  If the projection crosses 5,000,000,000 bytes, stop early, record
  `target_size_projection_failed`, return the variant to `selected`, and
  restart with a higher CQ or an explicit bitrate. Do not finish an output
  that cannot be uploaded.

## Flow

1. When processing a new batch, preserve release-first coverage: start no second supplemental encode for a covered work while another eligible new work still lacks a first releaseable variant, unless that other work is blocked or waiting on external input.
2. Probe source streams with `../../scripts/probe-media.mjs` or direct `ffprobe`. For BDMV `STREAM/*.m2ts`, prefer `probe-media.mjs`: it also reads matching CLPI PGS language descriptors when ffprobe leaves subtitle languages blank. Chinese subtitle eligibility requires either a verified Chinese stream descriptor or stronger sampled evidence; never infer it from the presence of a `zho` audio track. When several BDMV PGS streams all report `zho`, render a dialogue-bearing sample from every candidate ordinal and record its observed treatment separately (Simplified, Traditional, bilingual, or unknown). A shared CLPI language code does not distinguish those treatments and is not enough to choose the burn-in stream.
3. Identify HDR/DV/color risk, subtitle tracks, audio tracks, duration, resolution, and frame rate.
4. For uncertain color/subtitle timing, make a short sample before full encode. A language tag alone does not prove that a subtitle stream contains Chinese text. A bounded sample is a hard gate: run the encoder's strict smoke path, inspect its stderr/exit status, and extract frames at one or more known dialogue timestamps. Any decoder error, green/flat/magenta frame, frozen frame, missing expected picture, or absent dialogue subtitle means the source/stream/tone-map choice is blocked; do not start the full encode because the command happened to exit 0.
   If the sample/probe cannot read the source before its bounded timeout, classify the relevant evidence as unknown and record the I/O failure. Do not translate that failure into `no subtitle`, `no audio`, a rejected source, or a deferred catalog-metadata task.
   When a subtitle-dependent source has no usable internal, sidecar, or hard subtitle, route it through `wwp-subtitle-acquirer`. Do not start a full encode from an unranked provider result; first obtain an authorized local artifact and pass compatibility, language, coverage, beginning/middle/end timing, and visual sample checks.
5. Treat dark/flat/green/magenta HDR-to-SDR samples as a blocker for final delivery until a validated tone-mapping or HDR-preserving path is chosen. Do not upload or create a playable Media Assets row for a visibly wrong-color encode.
6. Choose subtitle/audio variants using `../../references/encoding-rules.md`.
7. Before starting a long encode, prepare the Notion destination through `wwp-notion-publisher` when the result may be API-uploaded or manually uploaded. Record the movie spec page ID, or the series spec and episode page IDs, so finished files have a precise upload target. Preparation must also prove that the intended destination is empty. If the exact movie spec already contains a video block, stop before encoding and evaluate the existing playable asset; do not treat reuse of that page as successful preparation for a new encode. Claim one encode/remux owner for the variant and exact output path; inspect active ffmpeg command lines before every retry, stop duplicate owners, and run only one final remux writer against the preserved work file.
   For a long local encode, an optional one-shot postprocess watcher may wait on the exact encoder PID and generate ffprobe/QC artifacts. Its terminal state is only `qc_ready`; inspect the artifact and explicitly record `qc_passed` before upload. Never let a background watcher mark QC, upload, or website release by inference.
8. Use `../../scripts/plan-stream-variants.mjs` when combining hard subtitles, soft subtitles, Mandarin/Cantonese/original/commentary audio, or director cuts.
   Before re-encoding the picture for an audio-only variant, look for a QC-passed MP4 with the exact same cut, duration, framing, resolution, color treatment, and burned-subtitle pixels. When all visual facts match, copy that `hvc1` video stream and encode or remux only the requested source audio. This is especially valuable when direct decoding of a source track such as TrueHD makes the full video pipeline slow. It is forbidden across different cuts, subtitle treatments, crops, tone maps, or incomplete parents. Probe the final file and verify that the copied video duration and packet hash match the parent; do not use `-shortest`.
9. Use `../../scripts/transcode-hevc-mp4.mjs` for the standard PGS-to-HEVC/MP4 path, pass `--subtitle-stream none` for verified hard-sub sources, or pass `--subtitle-file <ass|ssa|srt>` for extracted text subtitles. For non-UTF-8 sidecars, add the verified `--subtitle-charenc` value. The default is `--video-encoder auto`: probe the encoder with a real frame, prefer `hevc_videotoolbox` on macOS and NVENC on Windows/Linux, and fall back to `libx265` before encoding if hardware is unavailable. An explicitly requested encoder fails rather than silently changing the plan. Apple quality uses `--vt-quality` (1-100, default 65), independently of NVENC CQ/x265 CRF; use explicit bitrate for size-oriented variants. Never carry `p5`, `-cq`, or `-crf` into VideoToolbox. CPU fallback is still subject to the same subtitle, audio, color, size, ffprobe, and playback gates. Run it first with `--duration` for a bounded smoke sample; bounded runs use FFmpeg's strict error mode and must be treated as failed on decoder errors. `--allow-decoder-recovery` is an explicit source exception only when the decoder error is isolated to a recoverable selected audio stream and an independent audio probe (real duration plus non-silent waveform) is recorded; it is never a general way to turn decoder failures into success. Extract and inspect at least one frame at a known dialogue timestamp, and preferably more than one timestamp for a color-risk source. A frame without visible subtitles, or a command that exits 0 after decoder errors without the recovery evidence, is not a successful smoke test. The script encodes to MKV and remuxes to MP4 so a late MP4 mux failure cannot be mistaken for a complete output. After final probe, rename a pre-created spec, output filename, ledger spec key, expected filename, and target bytes together when the actual decimal-GB tier rounds differently from the plan. Do this before upload so Notion, Media Assets, and the ledger never retain a planned size as measured fact.
   Probe the selected subtitle stream's last packet timestamp before the full run. The bitmap overlay must pass through the base video after subtitle EOF, and a full encode must not use `-shortest`; otherwise a subtitle or audio stream ending early can silently remove closing footage. Final duration must match the source video within normal container tolerance.
   When it runs in the background, read its stdout `out_time_ms` and `progress` records. A long encode is active only when its progress timestamp advances; do not infer a stall merely from a delayed directory-size refresh. `progress=end` is not final acceptance: still probe the final MP4 and run decode checks. If an FFmpeg null-mux decode emits non-monotonic DTS warnings, do not fail the file from that warning alone; audit the final container's video packets with ffprobe, where strictly increasing packet DTS is the authoritative timestamp gate. When inspecting running encoders on Windows, treat a package-manager shim and its child executable as one ownership chain. A duplicate owner exists only when independent processes can write the same final or work path.
   Use `--scale 1920x1080` when the intended spec is 1080p and the source is 4K; keep the scale choice in the production manifest. Use `--video-bitrate <rate>` when the target spec is size-oriented, calculating the rate from duration, audio overhead, and the 5GB cap; use `--cq` for exploratory or compact outputs. If the source stream's declared frame-rate fields conflict with measured packet timestamps and the default encode fails duration validation, derive the rational rate from the source timeline and pass `--video-frame-rate <numerator/denominator>`; record both the declared metadata and packet-timing evidence in QC. Do not relax the duration gate to mask a frame-rate mismatch. For a confirmed HDR/Dolby Vision source, use the explicit `--tone-map-sdr` option only after a short sample proves BT.709 output and acceptable colors. Do not apply it to ordinary SDR sources.
10. Generate QC artifacts, including contact sheets when helpful.
11. Probe final files and preserve the JSON/manifest for Media Assets. For HEVC/MP4, require `codec_tag_string=hvc1`; an `hev1` result must be losslessly remuxed and re-probed before Android-browser delivery.
12. Verify the final byte size is below the Notion playable upload limit before calling it upload-ready.
13. Import the final QC manifest into the local ledger with `node tools/film-ledger.mjs import-production-manifest --production-manifest <manifest.json> --json`. A local encode is not removed from the workflow at this point: its ledger entry remains until the pre-created Notion structure, uploaded media block, and Media Assets row are all verified.

## First-Release Scheduling

- Default to a compact first release because it minimizes time to a watchable website entry.
- If high and compact tiers are both already selected, encode the higher reusable visual stream first only when it will not materially delay first release and the compact output can be derived from it without avoidable quality loss. Upload the high tier while deriving compact. Otherwise encode compact directly from the best source first and return to the high tier after batch coverage.
- When deriving compact from an existing QC-passed high tier, first inspect real dialogue frames from that exact parent to verify the visible subtitle script. Do not inherit `简`/`繁`/bilingual labels from filenames, old spec titles, or ledger text. Correct the parent spec, Media Asset, ledger variant, and planned derivative together when the pixels contradict those labels.
- Do not run competing GPU encodes merely to appear parallel. While GPU encoding is active, use CPU/network/attention capacity for metadata backfill, destination preparation, upload, Media Assets reconciliation, and QC of completed files.

- When the final output volume is too full to hold both the temporary MKV and the final MP4, use `--temp-dir <other-volume>` with `transcode-hevc-mp4.mjs`. Keep `--output` in the configured output directory; only the intermediate work files may move to the temporary volume. The temporary volume must be checked for sufficient free space before starting, and the final output still requires its own free-space check.
- `G:` may serve as that temporary volume when it is actually mounted and a
  write/read probe confirms acceptable operation. It is an optional external
  fallback, not a fixed output directory; do not place the final output there
  unless the selected output root is explicitly G-based and recorded in the
  ledger.
- For external SSA/ASS/SRT subtitles, verify the text encoding before a full batch. A non-UTF-8 sidecar must use `--subtitle-charenc` (for example `GBK`) and pass a bounded smoke test with visible dialogue before the batch is selected for encoding.
- For multichannel AAC browser delivery, pass the explicit source channel count (`--audio-channels 6` for 5.1 or `--audio-channels 8` for 7.1) so the output carries a channel layout. A file that lacks this layout fails browser-compatibility QC even if FFmpeg completes.
- A first release is allowed to complete before supplemental variants. Keep every planned supplement as a concrete selected/deferred ledger variant so it returns to the production queue and keeps the source retained.

When starting `ffmpeg.exe` in the background from PowerShell, pass a single explicitly quoted command-line string to `Start-Process -ArgumentList`; do not pass an unquoted argument array. Probe the exact source path with a one-second direct `ffmpeg` read first when it contains spaces or punctuation such as `!`, then confirm the background log advances before treating the encode as started.

If a full encode burns PGS subtitles and the direct MP4 muxer returns FFmpeg's `AVERROR_PATCHWELCOME` / `Not yet implemented in FFmpeg, patches welcome` at the end of the stream, treat the result as incomplete rather than QC-passed. Preserve the log, discard the corrupt `.part` after diagnosis, rerun the video encode to a Matroska intermediate, then perform a separate stream-copy remux to MP4 with `-tag:v hvc1`. Probe the finalized MP4 and confirm duration, stream count, and byte size before handoff; do not use the corrupt `.part` as a recovery source.

## Variant Rules

- Subtitle priority is Traditional Chinese-English bilingual, Simplified Chinese-English bilingual, Traditional Chinese, then Simplified Chinese.
- For foreign-language works, original-language audio is the baseline branch and dubbed audio is supplemental. Produce or explicitly defer the compact original-audio variant before treating the audio matrix as covered. For high-value films, normally add the higher-bitrate original-audio variant before an equivalent dubbed high tier; a dubbed high tier may coexist but cannot silently replace it.
- When the selected source audio is TrueHD, DTS-HD MA, DTS:X, Atmos-in-TrueHD, or another complex lossless/multichannel track that makes the combined video/audio encode fall below realtime, use the encoder's split-audio path (`--split-audio`). Encode the video and audio independently, then remux them without `-shortest`; record that path in QC so a slow audio decode cannot silently make a production task appear stuck.
- Hong Kong films prefer Cantonese plus Chinese subtitles first; Mandarin can be supplemental when available.
- Make a verified Mandarin variant by default for children's, animation, and family titles, and when it fills a valuable missing Mandarin/Cantonese spec on an existing library work, provided the normal production gates pass.
- For ordinary foreign-language films and supplemental Mandarin versions of Hong Kong films, ask the user before adding the `国配` output. State whether compact and higher-bitrate tiers are planned and how many extra files the Mandarin choice would create; explicit approval is required before doubling a multi-bitrate matrix.
- Missing Chinese subtitles on an accepted, verified `国配` branch are optional later enrichment, not a failed subtitle gate. Encode it with `--subtitle-stream none`, label the spec from verified audio/codec/size facts without a subtitle tag, and record the limitation in the production manifest and AI completion note. Keep any separate foreign-original-audio branch routed through the normal Chinese-subtitle gate.
- Treat a source label such as `Chinese`, `zh`, or a filename marker as insufficient to identify Mandarin versus Cantonese. When a disc has multiple Chinese audio streams, preserve the stream IDs and verify the mapping by trusted source evidence or human listening before naming a result `国配`, `粤配`, or `台配`.
- If the user reports that a finished file sounds Cantonese, treat that report as the current audio evidence and route it to a `粤配` spec. Do not create or claim a `国配` spec until a Mandarin stream is separately verified; if it is not verified, leave the Mandarin variant for later rather than guessing.
- When a verified commentary track exists and Chinese subtitles or Chinese assistance make it usable, prefer producing that commentary spec when capacity permits. Prefer a director/filmmaker commentary when available, keep the selected audio ordinal and title in the manifest, reuse the QC-passed video stream, and remux the commentary audio without re-encoding the video. This is a preferred supplemental branch, not a requirement to duplicate every bitrate tier.
- Director cuts should be considered as separate valuable specs.
- Multiple subtitle variants are optional capacity work, not a hard requirement; report available subtitle tracks and produced variants.

## Completion Gate

Before handing off to Notion, report final path, exact byte size, whether it is below the Notion playable upload limit, target Notion page ID(s), ffprobe-derived metadata (including the HEVC `codec_tag_string`), selected subtitle/audio tracks, QC result, and any known limitations.

## macOS Runtime and Recovery

Read `../../references/mac-transcoding.md` before Mac production. Helpers prefer the installed Homebrew `ffmpeg-full` plus its sibling ffprobe; explicit CLI options or `WWP_FFMPEG` / `WWP_FFPROBE` override this. Capability checks and real encoder probes precede the encode. CPU tone mapping is selected when CUDA is unavailable. A requested libplacebo path must prove a working Vulkan device; do not install a new GPU stack or weaken HDR QC just to bypass a failure. Dolby Vision Profile 5 must not go through ordinary CPU PQ tone mapping.

Text subtitles are staged under safe filenames. Keep embedded ASS styling and font attachments; on Mac, record missing CJK-font substitutions while preserving timing, color, alignment and size. Missing glyph diagnostics fail the encode. Inspect dialogue frames even after a successful command. The source subtitle is never modified.

Every encode owns an exclusive output lock and a dedicated `.wwp-encode-*` work directory with `state.json` and `ffmpeg.log`. Existing final outputs are never overwritten. On failure, preserve the work directory. `--resume` requires an identical source/plan and a completed video/audio/remux checkpoint, which is probed and decoded before reuse. An interrupted partial encode must use explicit `--restart-work`; that restarts only this job's retained files. `--recover-lock` may remove only a dead local owner's lock; a live or other-machine owner requires investigation. Keep the same tool/source/storage configuration when resuming.

Use the Node `make-qc-contact-sheet.mjs --input <media> --output-dir <qc-dir>` on every platform; optional `--wait-pid <pid>` waits for one exact process with a bounded deadline. It generates probe, sampled frame and decode evidence and writes only `qc_ready`, never `qc_passed` or publication. The encoder uses `caffeinate` for its Mac lifetime and forwards termination signals to FFmpeg. Re-probe storage after any interruption. Validate actual browser playback separately from codec/container checks.

- HDR-to-SDR helpers record source/output colorimetry and the tone-map algorithm in the job plan. Deliver BT.709 with explicit limited-range metadata; apply ordered dithering when reducing HDR precision to 8-bit, and validate output tags before publication. The CPU path adds delivery padding only after tone mapping. Reuse the per-job source probe, but probe work and delivery files independently. Keep automatic filter threading unless measured evidence on the actual hardware justifies an override; use `../../references/mac-transcoding.md` for the current benchmark evidence.
